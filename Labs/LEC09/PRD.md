# PRD — 소닉 애니메이션 뷰어 (LEC09)

> 근거 문서: [PRE-PRD.md](PRE-PRD.md)

## 1. 개요

`sonic-sprite.png` 스프라이트 시트에 들어 있는 소닉의 모든 동작을 순서대로 재생하는 애니메이션 뷰어를 만든다.
각 동작은 5회 반복 재생하고 1초 쉰 뒤 다음 동작으로 넘어가며, 마지막 동작이 끝나면 처음부터 무한 반복한다.
걷기·달리기처럼 이동이 포함된 동작은 제자리에서 재생하지 않고 화면 위를 실제로 이동하면서 재생한다.

## 2. 개발 환경 및 제약

| 항목 | 내용 |
|---|---|
| 언어 | Python 3 |
| 라이브러리 | pico2d (외 런타임 의존성 없음) |
| 결과물 파일 | `Labs/LEC09/sonic_animation_visualer.py` (**단일 파일**) |
| 리소스 | `Labs/LEC09/sonic-sprite.png` |
| 브랜치 | `drill9` |

- 별도의 모듈, JSON 매니페스트, 설정 파일을 두지 않는다. 프레임 좌표 등 모든 데이터는 결과물 파일 안에 넣는다.
- 프레임 좌표를 측정할 때 보조 도구(Pillow 등)를 써도 되지만, 그 도구는 결과물에 포함하지 않는다.
- 스크립트를 어느 작업 디렉터리에서 실행하더라도 이미지를 찾을 수 있도록, 이미지 경로는 스크립트 파일 위치를 기준으로 계산한다.

## 3. 리소스 분석 (sonic-sprite.png)

- 크기: 399 × 525 px, RGBA 형식, 배경은 투명(alpha = 0)이다.
- 맨 위에 제목 텍스트("Classic Sonic Sprites")가 있고, 맨 아래에 제작자 크레딧 텍스트와 다른 캐릭터 그림이 있다. 둘 다 **재생 대상에서 제외**한다.
- 그 사이에 소닉 프레임이 행(row) 단위로 배치되어 있다. 프레임은 대략 30~50 px 크기이다.
  - 행마다 프레임 개수가 다르다.
  - 같은 행 안에서도 프레임마다 폭과 높이가 다르다.
  - 한 행에 여러 동작이 섞여 있는 경우가 있다. 예: 달리기 행 끝의 브레이크·스핀 동작, 하단 행의 위 보기 / 아래 보기 / 피격 동작.
- 구현 단계에서 프레임을 측정해 확정한 동작은 **17종, 76프레임**이다.

  | 시트 행 | 동작 (프레임 수) |
  |---|---|
  | 1 | Idle (7), Look Up (2), Duck (2) |
  | 2 | Walk (8), Jog (4) |
  | 3 | Run (4), Kick (2) |
  | 4 | Spin Dash (9) |
  | 5 | Roll (6) |
  | 6 | Sprint (6) |
  | 7 | Peel Out (6) |
  | 8 | Turn Around (6), Hurt (2) |
  | 9 | Push (4), Brake (4) |
  | 10 | Surprised (2), Victory (2) |

- 1행에는 서로 맞닿은 프레임이 있다. 경계는 잘리는 픽셀이 0개가 되는 열(x = 86, 211, 240)로 정했다.

## 4. 기능 요구사항

### FR-1. 프레임 데이터
- 동작마다 `이름`과 프레임 사각형 목록을 정의한다. 프레임 사각형은 `(left, bottom, width, height)`이고, pico2d 좌표계(좌하단 원점)를 따른다.
- 이 데이터로 **시트에 있는 소닉의 모든 동작**을 빠짐없이 다룬다. 단, 3장에서 제외한 텍스트와 크레딧 영역은 넣지 않는다.
- 동작마다 프레임 수와 프레임 크기가 달라도 재생에 문제가 없어야 한다.

### FR-2. 프레임 출력
- `Image.clip_draw()`로 현재 프레임 영역만 잘라서 그린다.
- 제자리 동작은 화면 가로 중앙에 그린다. 이동 동작의 가로 위치는 FR-8을 따른다. 세로 방향은 모든 동작에서 **바닥선(발 위치)을 고정**한다. 프레임 높이가 바뀌어도 캐릭터가 위아래로 흔들리지 않게 하기 위해서다.

### FR-3. 확대
- 원본 프레임은 화면에 비해 매우 작으므로 충분히 확대해서 그린다.
- 확대 배율은 **동작 단위로 하나**만 정한다. 기준은 그 동작에서 가장 큰 프레임이 화면 높이의 약 50%를 차지하도록 하는 것이다. 같은 동작 안에서 배율이 프레임마다 바뀌면 캐릭터 크기가 출렁이기 때문이다.
- 가장 넓은 프레임도 화면 밖으로 잘리지 않아야 한다.
- 픽셀 아트가 흐려지지 않는 방식을 우선한다. 예: 정수 배율 사용.

### FR-4. 재생 순서
1. 현재 동작을 처음부터 끝까지 재생하는 것을 1회로 센다. 이를 **5회** 반복한다.
2. 5회가 끝나면 **1초** 동안 쉰다. 쉬는 동안에는 마지막 프레임을 계속 보여준다.
3. 다음 동작으로 넘어간다.
4. 마지막 동작까지 끝나면 첫 동작으로 돌아가 **무한 반복**한다.

### FR-5. 재생 속도
- 프레임 전환 간격은 동작별로 정할 수 있게 한다. 예: 대기는 느리게, 달리기와 구르기는 빠르게.
- 프레임 전환과 1초 정지는 경과 시간 기준으로 계산한다. 그래야 실행 환경의 프레임 속도와 상관없이 같은 시간이 걸린다.

### FR-6. 정보 표시
- 화면에 현재 동작 이름, 반복 횟수(예: `3 / 5`), 정지 중인지 여부를 텍스트로 표시한다.
- 폰트는 pico2d에 함께 들어 있는 폰트를 쓴다. 특정 OS의 폰트 경로를 하드코딩하지 않는다.

### FR-7. 종료
- 창 닫기 버튼(`SDL_QUIT`)이나 `ESC` 키를 누르면 프로그램을 정상 종료한다.

### FR-8. 이동 동작
- 이동이 포함된 동작은 재생하는 동안 캐릭터가 화면 오른쪽(시트에서 캐릭터가 향한 방향)으로 이동한다.

  | 동작 | 이동 속도 (px/s) |
  |---|---|
  | Walk | 120 |
  | Jog | 220 |
  | Run | 320 |
  | Roll | 380 |
  | Sprint | 420 |
  | Peel Out | 520 |

  - 속도는 동작이 빠를수록 크게 잡아, 다리 움직임과 이동량이 대략 맞게 한다.
  - 나머지 동작은 제자리 동작이다. 예: Spin Dash는 차징이고, Push는 벽을 미는 동작이다.
- 이동 동작은 **화면 왼쪽 밖에서 출발**해 화면 안으로 들어온다.
  - 처음에는 중앙에서 출발하도록 정했지만, 그러면 5회 이동 후 쉬는 위치가 화면 오른쪽 가장자리에 걸렸다(예: Walk가 x ≈ 881).
  - 왼쪽 밖에서 출발하면 6개 이동 동작 모두 쉬는 위치가 화면 안에 들어온다. Walk는 x ≈ 352, Peel Out은 x ≈ 624이다.
- 캐릭터가 화면 오른쪽 밖으로 완전히 나가면 왼쪽 밖에서 다시 들어온다(화면 순환).
- 이동량은 경과 시간 기준으로 계산한다. 계산식은 `속도 × dt`이다.
- 5회 재생 후 쉬는 1초 동안에는 이동도 멈춘다.
- 다음 동작으로 넘어가면 가로 위치를 그 동작의 시작 위치로 되돌린다. 제자리 동작은 화면 중앙, 이동 동작은 왼쪽 밖이다.
- 이동 동작 중에는 정보 텍스트에 이동 속도를 함께 표시한다. 예: `move 120 px/s`.
- 이동 속도는 동작 데이터와 함께 결과물 파일 안에 정의한다.

## 5. 비기능 요구사항

- **가독성**: 매직 넘버를 상수로 뺀다. 예: 반복 횟수 5, 정지 시간 1초, 화면 크기, 목표 표시 비율.
- **구조**: 재생 상태(현재 동작, 프레임, 반복 횟수, 정지 타이머, 가로 위치)는 하나의 클래스로 관리한다. 메인 루프는 이벤트 처리 → 갱신 → 그리기 순서로만 이루어지게 단순하게 유지한다.
- **안정성**: 이미지 파일이 없으면 원인을 알 수 있는 오류 메시지를 출력한다.

## 9. 진행 로그

7장의 단계 계획대로 24단계를 진행했고, 단계마다 실행해 확인한 뒤 커밋했다.

- **1–5단계**: 창, 상수, 종료 이벤트, 이미지 로드, 시트 전체 출력.
- **6–11단계**: Idle 프레임 데이터를 넣고 단일 프레임 → 애니메이션 → 시간 기반 전환 → 확대 → 바닥선 고정 순으로 만들었다.
- **12–15단계**: `AnimationPlayer` 클래스로 분리한 뒤 5회 반복, 1초 정지, 무한 순환을 차례로 붙였다.
- **16–18단계**: 나머지 동작을 시트 행 단위로 추가했다.
- **19–22단계**: 배율 상한, 동작별 속도, 정보 텍스트, 단색 배경과 바닥선.
- **23단계**: 프레임 좌표를 전수 점검했다. 소닉 픽셀이 빠진 곳이 없는지, 테두리에서 잘리는 그림이 없는지 확인했다. 1행에서 이웃 프레임 픽셀이 섞이던 경계 2곳을 고쳤다.
- **24단계**: docstring과 주석 정리.
- **25–28단계 (이동 동작, FR-8)**:
  - 이동 속도 데이터(`MOVE_SPEED`)를 넣고, 가로 위치 상태와 시간 기반 이동, 화면 순환을 붙였다.
  - 시뮬레이션해 보니 중앙에서 출발하면 쉬는 위치가 화면 가장자리에 걸려서, 이동 동작은 왼쪽 밖에서 출발하도록 바꿨다.

결과물 확인 방법:
- 스크린샷으로 화면을 확인했다.
- 재생 로직은 시뮬레이션 테스트로 확인했다. 5회 반복, 1초 정지, 17개 동작 순환이 맞게 동작한다.
- 이동도 시뮬레이션으로 확인했다.
  - 이동 동작 6종의 출발 위치와 쉬는 위치가 맞고, 쉬는 위치가 모두 화면 안에 들어온다.
  - 정지 중에는 이동하지 않는다.
  - 화면 순환은 27단계 시뮬레이션에서 확인했다. 그때는 중앙에서 출발했고, Jog가 x 925 → -126으로 넘어갔다.
  - 왼쪽 밖에서 출발하는 지금 설정에서는 5회 재생 동안 오른쪽 끝에 닿지 않는다. 그래서 순환은 속도를 올리거나 재생 시간이 늘어날 때를 위한 안전장치로 남겨 두었다.
- ESC 키 이벤트를 실제로 넣어 프로그램이 종료되는 것을 확인했다.
